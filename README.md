# 6807Mlight · 状态灯桥接与七色固件

> 一句话：让 6807AI状态灯MLight（那个 USB 状态灯）识别 **DeepSeek Harness（DSH，命令行/Web 版）** 和 **Claude Code 终端版** 的运行状态——正在干活亮黄灯（呼吸），等你确认闪红灯，空闲绿灯。仓库里还带了这盏灯自己的 **七色固件** 源码。

## 装机前提（缺一不可）

1. **macOS 13 以上**的 Mac。
2. 已安装 **6807AI状态灯MLight 1.2.1**（`/Applications/6807AI状态灯MLight.app`）——**没装也没关系**，安装器会自动挂载仓库 `原厂原始包/` 里的 dmg 弹出官方安装器，你点一次「开始安装」即可（厂商是 GUI 向导且有 Gatekeeper 校验，这一下必须人工点）。
3. 已安装 **node v24 以上**（终端里 `node -v` 能看到版本）。安装器会自动从 PATH 或 `~/.nvm` 里找。
4. 想被识别的工具本身装好：DSH（有 `~/.dsh/sessions` 目录）、Claude Code（有 `~/.claude` 目录）。没装也不影响安装，只是灯不亮对应状态。

## 谁依赖谁（30 秒看懂）

```
USB 灯硬件（RP2040 Zero + 3 颗彩灯；固件可选原厂版或本仓库七色版）
  ↑ 全机只有 MLight 会通过串口给灯发命令
6807AI状态灯MLight（厂商软件：判定状态、点灯、开 6807 网页）
  ↑ 只读「骨架镜像」，永不接触你的真实会话
灯光桥接守护（本仓库：把 DSH / Claude 的状态翻译成骨架镜像）
  ↑ 只读
DSH 会话（~/.dsh/sessions）与 Claude 会话（~/.claude/projects）
```

- 桥接**不替代** MLight，是「喂数据」的：MLight 本体（原厂原始包里的 dmg）必须先装好。
- 固件是**可选改造**：原厂固件只有红黄绿三色且完全够用；七色固件向下兼容原厂全部命令。
- 桥接守护对 DSH / Claude 的会话**永远只读**，这是设计红线。

## 安装步骤

1. 把整个仓库 `git clone` 下来（或整文件夹拷到目标电脑，U盘、AirDrop 都行）——**要完整**，`原厂原始包/` 和 `桥接守护/` 都在里面。如果文件夹是从网上/微信传的，先在终端跑一句去掉隔离属性（git clone 的不用）：`xattr -dr com.apple.quarantine 6807Mlight`
2. 把灯插上 USB。
3. 双击 `安装.command`。如果系统不让运行：右键点它 →「打开」→ 再点「打开」。
   - 没装 MLight：它会自动挂载原厂 dmg 并弹出官方安装窗口 → 在「系统设置 → 隐私与安全性」里点「仍要打开」→ 窗口里点「开始安装」→ 装完安装器自动继续。
   - 已装 MLight：直接装桥接，一步到位。
4. 过程中若弹出「终端 想要控制 系统事件」的授权窗，点**允许**（这是清理旧版登录项用的，点拒绝也能装）。
5. 等它跑完显示「安装完成」，过 1~2 分钟（状态灯刷新慢）后双击 `自检.command` 确认全绿。

## 装完之后灯的规则（和状态灯原厂规则一致）

- 绿灯常亮：DSH / Claude / ChatGPT 至少一个「连接正常」且都没在干活。
- 黄灯呼吸：有回合（任务）正在运行。
- 红灯先闪后常亮：有工具在等你确认（提问/批准），红灯优先于黄灯。
- **DSH 的黄灯从「下一条新消息/新回合」开始亮**——状态灯原厂是增量设计，只统计它开始监视之后新开的回合，正在跑的老回合不补亮。

## 它在电脑上装了什么（心里有数）

1. `/Applications/灯光桥接.app`：一个不占资源的小守护程序（隐私版）。由 **launchd 代理 `local.mlight.dsh-bridge` 常驻**（崩溃/退出自动拉起，登录自启，日志在 `~/Library/Logs/灯光桥接/launchd.log`）。每 2 秒看一眼 `~/.dsh/sessions` 里有没有会话文件变动；有就在**内存里**解压解析，只把「无内容骨架事件」（回合开始/结束、提问/应答的标记）写进 `~/.mlight-dsh-mirror`。状态灯只读这些标记——**你的对话内容、文件路径、命令输出一个字都不会给它**；对 DSH 原文件永远只读。
2. Claude 同理：监看 `~/.claude/projects`（明文会话），在内存里解析后只把 user/assistant 的骨架标记（时间戳、权限模式、结束原因，内容全部是「.」）写进 `~/.mlight-claude-mirror/<项目>/<会话>/session.v1.jsonl`（v1.8 起改用这个命名，MLight 只认 `session.v*.jsonl`；14 天以上的过期骨架和空目录自动清理）。MLight 被环境变量指向该镜像，**再也不接触你的真实 Claude 会话**。实测：真实文件 99712 字节 → 骨架约 471 字节，内容指纹零泄漏。
3. launchd 代理配置：`~/Library/LaunchAgents/local.mlight.dsh-bridge.plist`。
4. 状态灯的开机启动配置（`~/Library/LaunchAgents/local.mlight.6807.autostart.plist`）里写入 5 个环境变量，告诉它：DSH 和 Claude 算已连接、DSH 的会话去镜像目录读、Claude 也读镜像、网络采样读假数据、只关心安装时刻之后的会话。
5. 日志在 `~/Library/Logs/灯光桥接/`（`mirror.log` 出错才写，超过 1MB 自动清空；`launchd.log` 是 launchd 的输出）。

## 隐私与安全要点（2026-10-31 审查结论）

- **读网络流量统计的 nettop 已彻底禁用**：MLight 原厂每轮会跑一次 30 秒的 `nettop` 读本机各进程流量字节（既拖慢灯的响应，也读你的网络统计）。本工具包用它的官方覆盖变量 `MLIGHT_CLAUDE_NET_BYTES` 指向一个写死「0 0」的假数据文件，nettop 从此一次都不会运行，灯的响应也从 10-30 秒降到 2-4 秒。
- **假数据文件**（`~/.mlight-dsh-mirror/.claude-net-bytes`）由守护自愈维持，`自检.command` 会检查它。
- 对 MLight 的逆向审查结论：仅监听本机 127.0.0.1:6807，60 秒持续观测零外联；未签名（adhoc）；只读各智能体会话目录、写自己的日志/配置、访问状态灯串口。

## 状态灯七色固件（改造部分）

原厂固件只认 RED/YELLOW/GREEN 三色。`固件源码/seven7.ino` 是改造后的七色固件 v1：

- 硬件：Waveshare RP2040 Zero + 3×WS2812B 串联，GPIO28（经 330Ω）→ DIN，GRB 800kHz。
- 串口 115200 8N1，一行一命令（`\n` 结尾），大小写不敏感，不回包。
- 保留原厂全部命令：`RED/YELLOW/GREEN × ON/BREATH/BLINK/OFF`、`BRIGHTNESS_n`、上电默认绿色 30% 亮度。
- 新增：`CYAN/BLUE/PURPLE/WHITE × ON/BREATH/BLINK/OFF`，共七色。
- 刷写：按住板上 BOOT 键插 USB，出现 `RPI-RP2` 盘后把 `七色固件v1.uf2` 拖进去。
- 装回后可用 `灯光实验台.command` 当场试每种颜色和动态（比如 `CYAN_BREATH`、`RED_ON+YELLOW_BLINK`）。

## 常见问题

**问：升级/重装了状态灯 MLight 之后，DSH 和 Claude 又变「未运行」了？**
答：它的安装器会重写自己的启动配置，把 5 个环境变量冲掉。重跑一遍 `安装.command` 即可（幂等，随便重跑）。

**问：换/升级了 node 版本？**
答：守护里写死了 node 路径。重跑 `安装.command`（会写入新路径）。

**问：灯一直不黄？**
答：先跑 `自检.command`。链路上任何一环断了它都会指出来。注意 DSH 要新回合才亮——给它发条新消息试试。

**问：想彻底删掉？**
答：双击 `卸载.command`。状态灯 MLight 本体不受任何影响（ChatGPT/Codex 的识别是它原厂自带的）。
